\section{Method}
\label{sec:method}

\subsection{Data Collection}
\label{sec:method-corpus}
\label{sec:method-language}

We collected reviews for 26 Islamic prayer-time and devotional apps from
Google Play on 2026-08-19, covering each app's review history to that date,
along with each app's store description, install count, and rating. This gave
732,194 reviews (Figure~\ref{fig:corpus}).

We chose apps purposively: we prioritised high install and review counts for
app-level comparison, favoured apps whose main purpose is salah (prayer times,
adhan, qibla, tracking) over general Islamic-lifestyle apps, and kept a few
smaller apps that were the only example of a feature category. This is not a
census or random sample; our claims are about these 26 apps, which we take to
represent the high-traffic core of the category.

Reviews were pulled with the store locale set to English and the United States,
newest first. This does not mean the corpus is entirely in English --- 48,265
of 324,687 texted reviews turned out to be non-English --- but it does mean we
see each app's English/US-locale slice, not its global review population.
Every app was collected the same way, so comparisons between apps remain fair;
what the decision limits is generalisation (\S\ref{sec:limitations}).

Filtering to reviews with text left 324,687 (\(C_{\mathrm{text}}\)). Running
fastText language identification on these gave an English subset of 276,422
reviews (\(C_{\mathrm{en}}\)), used for topic modelling.

\subsection{Sentiment and Aspect-Level Analysis}
\label{sec:method-sentiment}
\label{sec:method-aspects}
\label{sec:method-affect}
\label{sec:method-devotional-filtering}

We scored every review's sentiment two ways: a lexicon method (VADER) and a
transformer classifier (RoBERTa), reported throughout. Across all 324,687
texted reviews (Figure~\ref{fig:sentiment-agreement}), RoBERTa agrees with the
star rating at Cohen's \(\kappa=0.466\), more than twice VADER's 0.210. On a
500-review gold set hand-labelled into four categories, two annotators agreed
on 89.0\% of 100 double-coded rows (Krippendorff's \(\alpha=0.824\)) --- a
measure of labelling consistency, not classifier accuracy.

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{fig02_sentiment_agreement}
  \caption{Pairwise agreement between the three sentiment signals across the 324,687 texted reviews, row-normalised, with Cohen's \(\kappa\) per pair. RoBERTa tracks the star-derived label more closely (\(\kappa = 0.466\)) than VADER does (\(\kappa = 0.210\)).}
  \label{fig:sentiment-agreement}
\end{figure}

To track specific complaints and praise, we built a lexicon of 27 aspects
covering functional and experiential features (prayer-time accuracy, adhan
reminders, Quran audio, qibla, tracking, ads, monetisation, and more), using
340 keywords and 106 regex patterns applied sentence by sentence. We release
the full lexicon so readers can see exactly what triggers each tag.

Aspect keywords built for ordinary product reviews misfire on devotional
language. The clearest case: \texttt{goal\_system} scored 0\% precision
because reviewers often close a review with ``May Allah reward you,'' which
its keywords mistake for feedback about a goal-tracking feature. We removed
aspect tags whose triggering sentence was this kind of devotional formula ---
1,686 of 192,874 tagged (aspect, sentence) pairs (0.9\%), leaving 191,188. We
treat this as a real finding, not a cleanup step: general-purpose sentiment
tools do not transfer cleanly to religious text.

For RQ1 we also built two small keyword lists, one for guilt/anxiety language
and one for motivation language. These have no gold-standard validation, so we
treat what they produce as a lexical-frequency comparison, not a validated
measure of guilt, and rest RQ1's main claim on hand-coded review passes
instead (\S\ref{sec:rq1}).

\subsection{Demand Signals and Promise Extraction}
\label{sec:method-demand}
\label{sec:method-promise}

We used pattern matching to flag five kinds of demand signal, each tied to the
aspect it discusses: explicit requests, statements that a feature is missing,
churn (``I'm leaving because...''), stated preference (``that's why I use this
app''), and long-term use. Against a 200-row gold sample, precision was 91.5\%
overall. This gold sample was labelled against an earlier extractor run; a
later threshold change means only 11 of the 200 rows still match today's
extraction, so 91.5\% is our best estimate rather than an exact figure for the
current data.

To compare what apps promise against what they deliver, we extracted claimed
features from each store description and checked them against a hand-built
matrix (one row per app, one column per feature). Agreement is weak --- mean
Cohen's \(\kappa=0.272\) across 20 features, with four at \(\kappa=0\) purely
because one source records nearly every app as having, or lacking, that
feature, leaving no variance for \(\kappa\) to work with (raw agreement on
those same features still runs above 96\%). Mean raw agreement across all 20
features is 73.1\%. Figure~\ref{fig:promise-agreement} gives the full
breakdown.

\subsection{Topic Modelling}
\label{sec:method-topics}

We fit a BERTopic model over the 276,422-review English subset, using a seeded
UMAP reduction and a stopword list extended with Islamic terms and app names.
This produced 40 topics plus an outlier bucket: one large undifferentiated
``generic praise'' topic (168,054 documents, 61\%), an outlier bucket (62,745,
22.7\%), and 39 labelled topics covering the remaining 16\%. All topics were
hand-labelled. We treat the topic model as describing only the interpretable
minority of the corpus.

We fit three targeted sub-models for tracker discourse (RQ1), menstrual and
inclusion discourse (RQ4), and bloat discourse (RQ5). Because BERTopic's
output is sensitive to random seed, we refit each across five fixed seeds
(42--46) before inspecting any result. The tracker sub-model is stable (mean
pairwise Adjusted Rand Index 0.837); the bloat sub-model is not (6--11 topics
across seeds, ARI 0.452), so we treat its output as recurring themes rather
than a fixed partition.

\subsection{Statistical Models}
\label{sec:method-models}

We fit five mixed-effects regression models (M1--M5), each with a random
intercept per app to account for reviews clustering within 26 very different
apps: M1 (RQ2, cost of accuracy versus interface complaints), M2 (RQ1,
sentiment by tracker tier), M3 (RQ4, inclusion), M4 (RQ5, bloat and hardware),
M5 (RQ3, competitive-edge features). RQ6 is answered descriptively and enters
no inferential model. Where a mixed model failed to converge, we report a
cluster-robust OLS fit on the same data as a sensitivity check.

Coefficients from the five primary models enter one Benjamini--Hochberg
false-discovery-rate correction: 29 tests total, 20 surviving at
\(q < 0.05\). Eight terms in that set are technically non-converged --- huge
standard errors, \(p \approx 0.99999\) --- but we keep them in the denominator
for transparency; they account for eight of the nine terms that fail
correction. A further three return no standard error at all and sit outside
the correction entirely. The cause is structural: a random intercept per app,
fit over only 26 apps, cannot be separated from an app-level predictor in the
same model. We cite a null result only from a model that actually converged.

\subsection{Measurement Quality}
\label{sec:method-measurement}

Because several results depend on aspect tags, we checked their precision
against a 300-row gold sample (11 rows per aspect). Of these, 192 still match
under the current lexicon; unweighted precision across aspects is 69.3\%, and
corpus-volume-weighted precision is 84.4\% (95\% CI [79.7, 88.9]).
Table~\ref{tab:aspect-precision} breaks this down by aspect. Seven aspects fall
below 50\% precision, two at 0\%; every count drawn from one of these seven is
reported elsewhere only as a precision-adjusted estimate with a confidence
interval, never as a raw tagger count. Seventeen aspects sit at 64\% or higher
and supply almost all model input, with two flagged exceptions:
\texttt{madhab} (60\%, used in M1, and the one M1 term that reverses sign under
a robustness check) and the mosque-finder tagger used in RQ3 (27\%, where we
read only the direction of the effect, not its size).

\subsection{Ethics, AI Use, and Reproducibility}
\label{sec:method-ethics}
\label{sec:method-ai}
\label{sec:method-repro}

The corpus is public store review text; no users were recruited or contacted,
so this study needed no human-subjects review. We still treat it as data about
people: some reviews disclose menstruation, illness, or lapses in practice. We
report no reviewer names, quote verbatim rather than paraphrase, and choose
quotations with no incidental personal detail. Two quotations disclose
menstruation, chosen because RQ4's claim rests on users voicing that need
explicitly. We name applications throughout, including in criticism, since
they are public commercial products and the argument requires saying which app
did what.

All analysis code was written with the assistance of Claude Code, an AI coding
agent, used interactively by the authors. No generative model touched the
review text, labels, or reported statistics; every number here comes from code
run over the scraped corpus. The six research questions were pre-specified in
a written analysis plan before analysis began, and all gold-standard labels
were assigned by hand. One coding defect was found and fixed during analysis
and did not affect any reported statistic.

The analysis was run on 2026-09-03 at commit \texttt{5da2db7}; a from-scratch
re-run reproduced byte-identical output. We release the full pipeline, aspect
lexicon, feature matrix, gold and topic sheets, model output, and run manifest
at a URL supplied on acceptance, withheld here for anonymous review. We do not
release the raw review corpus, per the store's redistribution terms.
